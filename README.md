# Moonlit Waters — WPF

Приложение салона: WPF, .NET 8 для Windows, C# и Supabase.
Основа — присланный пользователем чистый WPF-шаблон.
Сохранены название проекта `Moonlit-Waters`, пространство имён `Moonlit_Waters`,
`.NET 8`, `AssemblyInfo.cs`, исходное решение `.slnx` и стартовый `MainWindow`.
Обычные XAML-окна и обработчики кнопок в `.xaml.cs`, без MVVM и DI.

- `main` — Avalonia для Linux, Windows и macOS.
- [`wpf`](https://github.com/v1waa/Moonlit-Waters/tree/wpf) — отдельная версия на WPF для Windows.

## Скачать и запустить

Нужны Windows и .NET 8 SDK. Из терминала:

```bash
git clone --branch wpf https://github.com/v1waa/Moonlit-Waters.git Moonlit-Waters-WPF
cd Moonlit-Waters-WPF
dotnet run --project Moonlit-Waters/Moonlit-Waters.csproj
```

В VS Code открыть именно папку `Moonlit-Waters-WPF`, где находится решение
`Moonlit-Waters.sln`. Установить рекомендованные расширения и нажать F5,
выбрав **Moonlit Waters — WPF**. Конфигурации запуска и сборки уже есть
в `.vscode/`. В Visual Studio открыть `Moonlit-Waters.sln` и нажать F5. Исходный
`Moonlit-Waters.slnx` также оставлен для новых версий Visual Studio.

Supabase уже подключён в `Moonlit-Waters/appsettings.json`.
Используются прежние логины и пароли из выданного владельцу `Доступы.txt`.
Пароли в GitHub не публикуются. SQL заново выполнять не нужно.

## Обновить только проект

В терминале **внутри папки репозитория**:

```bash
git pull --ff-only
```

Команда получает изменения текущей ветки только в этом репозитории.
Она не обновляет систему, .NET, VS Code или другие проекты.
Если локальные правки мешают обновлению, Git остановится: сброса файлов нет.
После обновления запустить проект обычной командой `dotnet run` выше.

## Окна и функции

| Окно | Для чего |
| --- | --- |
| `MainWindow` | Вход по логину и паролю |
| `DayWindow` | Записи на выбранную дату, статусы, выручка, свободное время |
| `ClientsWindow` | Клиенты, поиск, контактные данные и последний визит |
| `PricesWindow` | Категории, цены, длительность, добавление и архивирование услуг |
| `StaffWindow` | Мастера, контакты, специализация и часы работы |
| `ClientWindow` | Добавление и изменение клиента |
| `ServiceWindow` | Добавление и изменение услуги |
| `MasterWindow` | Добавление и изменение мастера, выдача логина и пароля |
| `AppointmentWindow` | Создание и изменение записи, выбор мастера и статуса |
| `MessageWindow` | Сообщения и подтверждения |

Каждый раздел — обычный `Window` со своими `.xaml` и `.xaml.cs` файлами.
Меню открывает выбранный раздел на месте предыдущего и закрывает предыдущее
окно. Сохраняются выбранная дата, размер, положение и развёрнутый режим.
Нажатие на текущий раздел не создаёт копию. Формы добавления и изменения
открываются отдельными диалоговыми окнами поверх текущего раздела.
Выход из аккаунта возвращает форму входа.

Календарь на русском, неделя начинается с понедельника. Дату можно выбрать
кнопкой календаря или ввести как `08.10.2026`. Некорректный ввод возвращает
предыдущую дату. Данные загружаются при открытии раздела, выборе даты и после
сохранения формы. Для ручного обновления остаётся F5; кнопка обновления и
смена пароля убраны.

Двойное нажатие на строку открывает редактирование. Мастер видит только
свои записи и связанных клиентов; прайс-лист и персонал доступны администратору.
Права проверяются также в базе. Дата и время — московские.
Примерные записи находятся на **08.10.2026**; в другой день список может быть пустым.
График мастера — ежедневные часы и флаг выходного.

## Структура

- `Windows/` — отдельные XAML-окна и их обработчики.
  `WindowNavigation.cs` переключает окна и завершает сеанс.
- `Models/SalonData.cs` — простые классы данных.
- `Services/SupabaseService.cs` — HTTP-запросы к серверным функциям.
- `App.xaml` — общие цвета и стили.
- `Styles/DatePicker.xaml` — поле даты, кнопка и календарь.
- `database/` — SQL для переноса в другой проект Supabase.
- `.github/smoke/` — проверка создания и отрисовки всех WPF-окон на Windows.

## Supabase

Используются таблицы `mw_staff`, `mw_clients`, `mw_services`, `mw_appointments`,
`mw_sessions`. В конфигурации находится только публичный publishable key.
Приложение обращается к RPC с проверкой сеанса и роли; прямой доступ к таблицам
запрещён, RLS включён. Вход без почты: bcrypt-хэш пароля, случайный токен сеанса
на 12 часов, в базе только SHA-256 токена. Сам токен хранится в памяти приложения.
После пяти неверных паролей вход блокируется на 15 минут.

База проверяет пересечение записей и часы работы. Цена сохраняется в записи,
поэтому изменение прайса не меняет прошлую выручку. Выручка — сумма завершённых
записей. «Свободных окон» — полные часовые интервалы с текущего времени до конца
графика мастеров на выбранную дату.

Файлы `database/00`–`04` нужны **только для первоначальной настройки новой базы**.
В новой базе выполнить их по порядку, сохранить пароли из результата
`02_accounts.sql` и изменить URL/публичный ключ в `appsettings.json`.

## Проверка

```bash
dotnet build Moonlit-Waters.sln --configuration Release
```

WPF работает только на Windows. `EnableWindowsTargeting` позволяет проверить
сборку из Linux, но не запустить интерфейс. GitHub Actions собирает проект
на Windows и проверяет создание и отрисовку 10 окон, поиск, календарь,
переключение разделов и меню мастера на данных в памяти.
Тестовая копия настроек использует локальный адрес, а не настоящую базу.
Снимки окон доступны в артефакте `wpf-window-screenshots`.

Время в формах WPF вводится как `10:30`, дата выбирается в календаре.
Для Visual Studio нужна рабочая нагрузка «Разработка классических приложений .NET».
